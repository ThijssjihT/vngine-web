Code walkthrough

How the engine is put together, for anyone who wants to read, fix or extend it. The pages follow the engine's subsystems rather than its files, because most subsystems run through several files.

Everything here describes the engine as of commit a080df2 (1 November 2026). All engine code lives under qml/engine/; the game itself lives under qml/game/ and is covered in Game authoring.

The shape of it

The engine is plain QML and ES5.1 JavaScript on Qt 5.6, with no C++ of its own. It falls into five layers:

  • GameEngine.js holds the story state and the rules: the loaded scene, the command pointer, labels, variables, conditions, style merging and sprite file validation. It is a .pragma library script, so there is one shared copy and it cannot see or create QML objects. Anything it needs from the QML side is handed in at start-up.
  • GameScreen.qml is the conductor. Its processNext() takes the next command from the engine and routes it — to the engine, to a component, or to a singleton — until a command needs the player. It also owns the session: starting, resuming and resetting a game.
  • Components draw what they are told: the textbox, the choice overlay, the sprite layer, and the typewriter that reveals text. They keep no story state.
  • Singletons — AudioController, Settings and SaveManager — exist once for the whole app, outside any page, so every page can reach them.
  • Pages are the Silica screens around the game: title, settings, load and save. GameScreen is a page too, and it never leaves the bottom of the page stack.

Pages in this walkthrough

Read them in this order the first time: they follow a game from start-up to a running scene, then the subsystems a scene calls on, and end with saving, which touches all of them.

File map

Where each file is explained. Paths are relative to qml/engine/, apart from the entry point.

FileWhat it doesExplained in
qml/harbour-vngine.qml Two-line entry point that creates the application window. Start-up and pages
components/VNgineApplicationWindow.qml Boot order: manifest, engine defaults path, settings, saves. Puts GameScreen at the root of the page stack, starts or resumes a game behind it, then pushes the title page on top. Start-up and pages
pages/TitlePage.qml Banner, title, tagline and credits from the manifest; first-run gesture hints. Start-up and pages
cover/CoverPage.qml The app cover. A placeholder for now. Start-up and pages
GameEngine.js Story state, JSON loading, scenes and labels, variables and conditions, style merging, sprite file validation. Command loop, Variables, Sprites, Style resolution
pages/GameScreen.qml The command dispatcher, choices, session start/resume/reset, the pulley menu, tap input, and assembling the layers. Also builds and restores the save blob. Command loop, Save system
components/Typewriter.qml Reveals dialogue one character at a time; a tap skips to the full line. Screen layers
components/TextboxLayer.qml The dialogue box, laid out from the resolved textbox style. Screen layers
components/ChoiceOverlay.qml The choice grid and its options, laid out from the resolved choice style. Screen layers
components/SpriteLayer.qml The on-screen sprite list, one image per asset, one timer per animation. Sprites and animation
engine_defaults/default_*.json One complete style per category. The bottom layer of every style, and the de facto schema. Style resolution
components/AudioController.qml Singleton. Music queue on two players for crossfades, a pool of one-shot effects, a pool of named looping effects. Audio
components/SfxSlot.qml One one-shot effect player in the pool. Audio
components/LoopFXSlot.qml One looping effect player with its own fade. Audio
components/Settings.qml Singleton. Builds the settings from the manifest and keeps them in LocalStorage. Settings
pages/SettingsPage.qml The settings screen, generated from what Settings holds. Settings
components/SaveManager.qml Singleton. The saves and flags tables, plus the staged save and staged load. Save system
pages/SaveGamePage.qml Pick a slot to save to. Save system
pages/LoadGamePage.qml Pick a save to load; rename and delete. Save system
components/Constants.js Database name and size, shared by Settings and SaveManager; save thumbnail size. Save system
components/qmldir Registers the three singletons. Architecture overview

Not in the engine yet

Worth knowing before you go looking for them: there is no HUD layer (a hud style is resolved and saved, but nothing draws it), no wait, end, show_hud or voice commands, and no text_key lookup — a keyed line shows as [key]. Unknown commands are logged and skipped.
