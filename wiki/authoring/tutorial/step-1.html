1. Set up your game folder

This guide assumes you have the Sailfish IDE installed. If not, please go to the Sailfish SDK installation guide and make sure you have the IDE installed.

Create the project

Open the Sailfish IDE, create a new project, and choose Sailfish OS Qt Quick Application under Application. Choose a name for your project. VNgine is designed with Harbour compliance in mind, and you are strongly encouraged to at least make your game available on Harbour. To keep your game Harbour compliant, make sure the project name is lower case and starts with harbour-, like VNgine is distributed as harbour-vngine.

On the next page, put a summary and a description. It is worth taking your time here, but you can always change it afterwards. Leave or change the version number, but if you choose to change it, make sure it contains only numbers, separated with dots.

The default build system, qmake, is the choice here, as I didn't test other build systems.

Select all kits. For Harbour, we need to supply both 64-bit (aarch64) and 32-bit (armv7) packages. The i486 kit is needed for the emulator.

I encourage you to use git as version control, but you are in no way required to. Please remember: if you use licensed assets in your game, it is not always legal to push them to GitHub. Please check whether you are allowed to open source your assets. You could always .gitignore some or all assets. This guide will not help you with this.

Press Finish to let the IDE build you a standard template.

The main QML file

After a few seconds, your new project is ready, and the file harbour-yourprojectname.qml is opened. Delete all code from this file. Copy the two lines from this code block, and paste them into your harbour-yourprojectname.qml.

import "engine/components" as Components
Components.VNgineApplicationWindow { }

This code is run when your application is started. All it does is initialise and start the game engine. We will add the engine and the game at a later stage. First, we need to look at permissions.

The desktop file

Permissions

VNgine needs permission to use audio. When you build and run in developer mode, the game runs without a sandbox, and sound seems to work. However, every time you start the game from your device, the sandbox will not allow sound to be played by default. We need to allow this ourselves. Open harbour-yourprojectname.desktop.

Under [X-Sailjail], set your OrganizationName as a reverse domain name. It doesn't have to be the reverse of a real domain you own, it just takes this form. Two examples:

com.firstnamelastname
org.forumhandle

Please keep the organisation name the same across all your projects.

Set your ApplicationName. It does not have to be the same as harbour-yourprojectname, but it should easily identify your application.

OrganizationName and ApplicationName are used in your game's folders. On every device the game is installed on, there will be an OrganizationName/ApplicationName folder, used for save games and other small files a user will generally not interact with.

Permissions should be set to Audio, so the full line reads Permissions=Audio.

Launcher name

With harbour-yourprojectname.desktop still open, let's look at the rest of the file. There are two lines you should change.

Name= is the name of your game as it is displayed in the app launcher. You should change the default harbour-yourprojectname to something more appropriate. For example, for the engine's example game, the default Name=harbour-vngine was changed into Name=VNgine Demo.

You can give your game different names for different locales. At the time of writing, a German name (Name[de]=) is active by default. Comment this line out, or change it to the German translation of what you put after Name=. By copying this line and changing the language code, you can add multiple translations of the name that is displayed in the launcher.

The project file

We are now done with the desktop file. Let's move on to the file that defines your project: harbour-yourprojectname.pro.

Find DISTFILES. It is appended with multiple files in your project. Remove these three lines:

    qml/cover/CoverPage.qml \
    qml/pages/FirstPage.qml \
    qml/pages/SecondPage.qml \

After the desktop file, add a space and a backslash ( \) and press Enter. Add the following two lines:

    $$files(qml/game/**, true) \
    $$files(qml/engine/**, true)

Every line should end with a backslash, except the last line. This DISTFILES variable tells the IDE to include all engine and game files in the project, so everything is included in the game package.

If you don't plan to translate your game, you might want to comment out the TRANSLATIONS and CONFIG lines.

Clean up the qml folder

Save all files. Open the project folder in your file browser and open the qml folder. In here, delete the cover and pages folders, with everything in them. The engine doesn't need these.

Add the engine

Clone the VNgine project from github.com/ThijssjihT/VNgine. If you don't know how this works, go to that page, click the green button that says <> Code, and choose Download ZIP. Extract the zip.

Whichever way you got the files, we are going to copy two folders and their contents: qml/engine and qml/game-directory-structure. Leave qml/game; this folder contains the sample game, which we won't need, but you might want to keep it around to look at some files as an example at any point.

Paste qml/engine and qml/game-directory-structure into your project's qml folder. Then rename qml/game-directory-structure to qml/game.

Build and run

The IDE should pick up all the files you just added. If not, close your project and re-open it.

Your project should now build and run. See if it does. Don't worry if you see errors; that is expected, as the engine tries to set up a new game that isn't there yet.

Your project is now completely set up and ready for your game, and you are ready for the next step in the tutorial.
