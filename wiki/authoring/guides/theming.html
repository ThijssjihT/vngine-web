Styles

A style is a small JSON file describing how one part of the interface looks. Styles come in categories — textbox, choice, hud — and can inherit from one another.

Path: qml/game/assets/ui/<category>/<style_id>.json

How a style is resolved

Three layers are merged, each overriding the one below:

  1. the engine default for that category (qml/engine/engine_defaults/default_<category>.json)
  2. the parent chain, if the file has a base
  3. the file's own style block

The merge is deep: setting background.color leaves background.opacity alone. That is why a style file only needs to list what it changes — everything you leave out keeps working, and keeps following the engine default if that default ever changes.

Inheritance

{
    "base": "boring_textbox",
    "style": {
        "background": { "color": "#3050c0" },
        "radius": 16
    }
}

A parent can have a parent of its own. The chain is followed to the end, then merged back down. Two rules to know:

  • A circular chain is detected, logged, and the whole style fails to load.
  • A base naming a file that will not load fails the whole chain — the engine does not silently fall back halfway.

The style id is a bare file name. Dots and slashes are rejected, so a style cannot reach outside its category folder.

If a style cannot be resolved at all, the engine warns and falls back to the engine default.

Applying a style

At the start of the game, from the manifest:

"default_styles": {
    "textbox": "boring_textbox"
}

Or during a scene:

{ "cmd": "style", "category": "textbox", "style": "colorful_textbox" }

The textbox style

These are the engine defaults. Anything you do not set behaves like this.

{
    "style": {
        "position": "bottom",
        "height": 0.25,
        "margins": { "left": 0, "right": 0, "top": 0, "bottom": 0 },
        "padding": { "left": 24, "right": 24, "top": 24, "bottom": 24 },
        "background": { "color": "#000000", "opacity": 0.7 },
        "border": { "width": 0, "color": "#000000", "opacity": 1 },
        "radius": 0
    }
}
KeyMeaning
positionbottom, center or top.
heightFraction of the screen height, 0 to 1.
marginsSpace outside the box, in scaled pixels.
paddingSpace between the box edge and the text, in scaled pixels.
backgroundFill colour and its opacity (0 to 1).
borderBorder width in scaled pixels, plus colour and opacity.
radiusCorner radius in scaled pixels.
Scaled pixels — every pixel value above (margins, padding, border width, radius) is multiplied by Theme.pixelRatio at render time. Write the numbers as they should look on a reference 540 px-wide screen and they stay proportionally the same on every device. height is a fraction, so it is not scaled.

Choice and HUD styles

Both categories currently have a two-key default:

{
    "style": {
        "color": "#000000",
        "opacity": 0.7
    }
}

Building one

The textbox style generator writes these files for you, with a live preview. It outputs only the values that differ from the default, which is exactly what you want in a style file.
