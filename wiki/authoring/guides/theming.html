Styles

A style is a small JSON file describing how one part of the interface looks. Styles come in categories — textbox, choice, hud — and can inherit from one another.

Path: qml/game/assets/ui/<category>/<style_id>.json

How a style is resolved

Three layers are merged, each overriding the one below:

  1. the engine default for that category (qml/engine/engine_defaults/default_<category>.json)
  2. the parent chain, if the file has a base
  3. the file's own style block

The merge is deep: setting background.color leaves background.opacity alone. That is why a style file only needs to list what it changes — everything you leave out keeps working, and keeps following the engine default if that default ever changes.

Inheritance

{
    "base": "boring_textbox",
    "style": {
        "background": { "color": "#3050c0" },
        "radius": 16
    }
}

A parent can have a parent of its own. The chain is followed to the end, then merged back down. Two rules to know:

  • A circular chain is detected, logged, and the whole style fails to load.
  • A base naming a file that will not load fails the whole chain — the engine does not silently fall back halfway.

The style id is a bare file name. Dots and slashes are rejected, so a style cannot reach outside its category folder.

If a style cannot be resolved at all, the engine warns and falls back to the engine default.

Applying a style

During a scene, with the style command:

{ "cmd": "style", "category": "textbox", "style": "colorful_textbox" }

The style is resolved from scratch each time, so it replaces the previous style of that category rather than adding to it. If it cannot be loaded, the engine warns and that category falls back to the engine default.

A save remembers the style id of each category and resolves it again on load, so a loaded game looks the way it did when it was saved, including any later edits to the style file.

Every new game and every loaded game starts from the engine default for all three categories, before the first style command or the saved ids are applied.

Planned — default_styles in the manifest, naming a style per category to use from the start of the game: 
"default_styles": {
    "textbox": "boring_textbox"
}
The manifest generator writes it and the sample game declares it, but the engine does not read it yet. Until it does, put a style command at the top of your first scene.

The textbox style

These are the engine defaults. Anything you do not set behaves like this.

{
    "style": {
        "position": "bottom",
        "height": 0.25,
        "margins": { "left": 0, "right": 0, "top": 0, "bottom": 0 },
        "padding": { "left": 24, "right": 24, "top": 24, "bottom": 24 },
        "background": { "color": "#000000", "opacity": 0.7 },
        "border": { "width": 0, "color": "#000000", "opacity": 1 },
        "radius": 0
    }
}
KeyMeaning
positionbottom, center or top.
heightFraction of the height left between the top and bottom margins, 0 to 1. All four margins apply whatever the position, so position only matters below 1.
marginsSpace outside the box, in scaled pixels.
paddingSpace between the box edge and the text, in scaled pixels.
backgroundFill colour and its opacity (0 to 1).
borderBorder width in scaled pixels, plus colour and opacity.
radiusCorner radius in scaled pixels.
Scaled pixels — every pixel value on this page (margins, padding, border width, radius, spacing, minimum height) is multiplied by Theme.pixelRatio at render time. Write the numbers as they should look on a reference 540 px-wide screen and they stay proportionally the same on every device. Fractions (height, width), opacities and columns are not scaled.

The text inside the textbox is not styleable yet: the speaker name uses the theme's highlight colour in bold, the dialogue the theme's primary colour, both at the small font size.

The choice style

The choice menu is a block (the grid) holding one box per option (the option). Again, these are the engine defaults.

{
    "style": {
        "grid": {
            "columns": 1,
            "spacing": 16,
            "width": 0.8,
            "margins":    { "left": 0, "right": 0, "top": 0, "bottom": 0 },
            "padding":    { "left": 0, "right": 0, "top": 0, "bottom": 0 },
            "background": { "color": "#000000", "opacity": 0 },
            "border":     { "width": 0, "color": "#000000", "opacity": 1 },
            "radius": 0
        },
        "option": {
            "min_height": 0,
            "padding":    { "left": 24, "right": 24, "top": 16, "bottom": 16 },
            "background": { "color": "#000000", "opacity": 0.7 },
            "border":     { "width": 0, "color": "#000000", "opacity": 1 },
            "radius": 0,
            "text":       { "color": null }
        }
    }
}
KeyMeaning
grid.columnsNumber of columns the options are laid out in. Columns share the block's width equally.
grid.spacingGap between options, horizontally and vertically.
grid.widthWidth of the block as a fraction (0 to 1) of the screen width left after the left and right margins.
grid.marginsSpace kept free around the block. The block is centred in what is left, both ways, so unequal margins move it. Its height always comes from its contents.
grid.paddingSpace between the block's edge and the options.
grid.background, grid.border, grid.radiusFill, border and corners of the block. The default background is fully transparent.
option.min_heightMinimum height of one option box. An option is otherwise as tall as its text plus padding.
option.paddingSpace between an option box's edge and its text.
option.background, option.border, option.radiusFill, border and corners of each option box.
option.text.colorColour of the option text. null uses the theme's primary colour.

Option text is centred and wraps to the box width. The game's qml/game/assets/ui/choice/flashy_choice.json shows a style that overrides most of these.

The HUD style

The HUD category currently has a two-key default:

{
    "style": {
        "color": "#000000",
        "opacity": 0.7
    }
}
Planned — the HUD itself. A hud style file can be written and switched to with the style command, but the engine does not draw a HUD yet (show_hud is not implemented), so it has no visible effect. Expect the schema to grow, as the textbox and choice styles have.

Building one

The textbox and choice style generators write these files for you, with a live preview. They output only the values that differ from the default, which is exactly what you want in a style file. A HUD style generator is planned along with the HUD.
