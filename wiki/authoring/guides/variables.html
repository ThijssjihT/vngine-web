Variables and conditions

Variables are how your story remembers things. Conditions are how it reacts to them: hiding a choice, taking a different branch, or changing what a character says.

Declaring

Variables are declared in the manifest with a starting value. On a new game the engine fills each one with its default.

"variables": {
    "panic": { "type": "int", "default": 1 }
}

Variables are saved and restored with the save game, so a loaded game continues with the values it had.

Changing a variable

{ "cmd": "set", "var": "panic", "op": "set", "value": 3 }
{ "cmd": "set", "var": "panic", "op": "add", "value": 6 }
{ "cmd": "set", "var": "gold",  "op": "from", "from": { "setting": "starting_wealth" } }
opEffect
setReplaces the value.
addAdds. An unset variable counts as 0.
subSubtracts. An unset variable counts as 0.
mulMultiplies. An unset variable counts as 0 — so multiplying an unset variable gives 0.

Instead of a literal value, a command can take its value from somewhere else with from:

"from": { "var": "gold" }              // another variable
"from": { "setting": "difficulty" }    // a settings value

An unknown op, or a value that resolves to nothing, is logged and ignored rather than crashing the scene.

Conditions

A condition is an object. It names what to look at, how to compare, and what to compare against.

{ "var":     "panic",      "op": "<",  "value": 3 }
{ "setting": "difficulty", "op": "==", "value": "hard" }
{ "flag":    "arachnofobia" }
KeyLooks at
varA game variable.
settingA value from the settings page.
flagA variable, falling back to a setting of the same name.

Operators: ==, !=, <, <=, >, >=. Comparison is strict, so 3 and "3" are not equal — keep your types consistent with what you declared.

With no op, the value is simply tested for truthiness: 0, an empty string and false are false, everything else is true. That is the short form for a flag.

No condition at all — a missing key or null — is true. An undefined variable or a missing comparison value is false, with a warning.

Where conditions are used

{ "cmd": "jump_if", "condition": { "var": "panic", "op": ">=", "value": 3 }, "label": "meltdown" }

And on choice options, to hide them until they are earned — see Scene script commands.

Showing variables in text

Wrap the name in percent signs. The engine looks for a variable first, then a setting.

{ "cmd": "say", "speaker": "Liisa", "text": "Like this, %player_title%?" }

Names must start with a letter or underscore and contain only letters, digits and underscores. An unknown name is left in the text as written, so a typo shows up on screen.
