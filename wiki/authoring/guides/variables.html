Variables and conditions

Variables are how your story remembers things. Conditions are how it reacts to them: hiding a choice, taking a different branch, or changing what a character says.

Declaring

Variables are declared in the manifest with a starting value. On a new game the engine fills each one with its default.

"variables": {
    "panic": { "type": "int", "default": 1 }
}

type is one of int, float, string or bool. Today it is documentation only: the engine reads default and nothing else, so a mismatch between the two is not checked. Keep them consistent yourself.

Variables are saved and restored with the save game, so a loaded game continues with the values it had.

Declaring is not strictly required: a set on a name that was never declared creates it on the spot. That also means a typo in a variable name quietly creates a new variable instead of failing, so declare the ones you use. The one exception that is created for you is the variable named by save_display_variable in the manifest, which is shown on the save slots; if you do not declare it, it starts out as "empty".

Changing a variable

{ "cmd": "set", "var": "panic", "op": "set", "value": 3 }
{ "cmd": "set", "var": "panic", "op": "add", "value": 6 }
{ "cmd": "set", "var": "gold",  "op": "set", "from": { "setting": "starting_wealth" } }
opEffect
setReplaces the value.
addAdds. An unset variable counts as 0.
subSubtracts. An unset variable counts as 0.
mulMultiplies. An unset variable counts as 0 — so multiplying an unset variable gives 0.

Instead of a literal value, a command can take its value from somewhere else with from. from replaces the value, not the op — the op is still one of the four above, so copying a setting into a variable is "op": "set" with a from block:

"from": { "var": "gold" }              // another variable
"from": { "setting": "difficulty" }    // a settings value

An unknown op, or a value that resolves to nothing, is logged and ignored rather than crashing the scene.

Conditions

A condition is an object. It names what to look at, how to compare, and what to compare against.

{ "var":     "panic",      "op": "<",  "value": 3 }
{ "setting": "difficulty", "op": "==", "value": "hard" }
{ "flag":    "arachnophobia" }
KeyLooks at
varA game variable.
settingA value from the settings page.
flagA variable, falling back to a setting of the same name.

setting is read live, so a change on the Settings screen takes effect the next time the condition is checked. Toggles, dropdowns, sliders and text fields are reached by the plain key you gave them in the manifest. Audio channels and language selectors have no short key and are meant for the engine, not for stories.

Operators: ==, !=, <, <=, >, >=. Comparison is strict, so 3 and "3" are not equal — keep your types consistent with what you declared.

With no op, the value is simply tested for truthiness: 0, an empty string and false are false, everything else is true. That is the short form for a flag.

No condition at all — a missing key or null — is true. An undefined variable, an unknown setting, a missing comparison value, an unknown operator or a condition with none of var, setting or flag is false, with a warning.

Variables and settings share names. In flag conditions and in %name% text the variable is looked up first, so a variable and a setting with the same name hide the setting. var and setting conditions only ever look in their own place. Avoid giving a variable the same name as a toggle, dropdown, slider or text field; the manifest generator warns when you do.

Where conditions are used

{ "cmd": "jump_if", "condition": { "var": "panic", "op": ">=", "value": 3 }, "label": "meltdown" }

And on choice options, to hide them until they are earned — see Choices. The effects of a choice option are set-style changes with the same keys: var, op and value or from.

Showing variables in text

Wrap the name in percent signs. The engine looks for a variable first, then a setting. This works in dialogue text, speaker names and choice option text.

{ "cmd": "say", "speaker": "Liisa", "text": "Like this, %player_title%?" }

Names must start with a letter or underscore and contain only letters, digits and underscores. An unknown name is left in the text as written, so a typo shows up on screen.

Planned — the design also describes built-in read-only variables: current_language, playtime_seconds and save_slot_label. They do not exist in the engine yet, so a script cannot read them.
