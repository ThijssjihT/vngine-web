Scene script commands

A scene is a JSON file holding a flat list of commands. The engine runs them one after another and only stops where the player has to do something — a line of dialogue to tap through, or a choice to make.

Path: qml/game/script/<scene_id>.json

Everything on this page can be written by hand, and everything on this page can also be built in the scene script generator, which draws the branching as a map and warns about the mistakes that are easy to make once a scene has more than one route through it.

{
    "id": "scene_0001",
    "commands": [
        { "cmd": "bg",  "image": "bg/centre_exterior_evening.png" },
        { "cmd": "say", "speaker": null, "text": "You are at your local community centre." },
        { "cmd": "jump", "scene": "scene_0002" }
    ]
}
Authoring rule — a scene must finish with a jump or an end. Running off the end of the command list is an authoring error; the engine warns and returns to the title page.

Implemented commands

CommandKeysWhat it does
sayspeaker, text Shows a line in the textbox with the typewriter effect and waits for a tap. "speaker": null means narration.
bgimage Sets the background, relative to assets/. Continues immediately.
spriteid, image, position Shows or replaces a sprite. Re-using an id swaps that sprite's image and position. Continues immediately.
sprite_removeidRemoves that sprite. Continues immediately.
setvar, op, value or from Changes a variable. See Variables and conditions.
labellabel A marker to jump to. Does nothing on its own. Labels are indexed per scene, so a label is only reachable inside its own scene.
jumplabel or scene Continues somewhere else.
jump_ifcondition + label/scene Jumps only when the condition is true, otherwise falls through to the next command.
choiceoptions Shows a menu and waits. See Choices.
stylecategory, style Switches the active style for textbox, choice or hud. See Styles mid-scene.
audio_bgaction and more Controls the background music: start, change volume, stop, pause, resume. See Audio.
audio_fxfile, volume Plays a one-shot sound effect. See Audio.
audio_loopaction, id and more Starts and stops looping sound effects such as rain or a crowd. See Audio.
endnone Finishes the story or a route. A stopgap for now: fades out the audio and returns to the title page, with no end card yet (that part is planned).

An unknown command is logged and skipped, so a typo will not stall the game — but it will not do what you meant either. That includes every command in the planned list below. Watch the console output while testing.

Dialogue

{ "cmd": "say", "speaker": null,    "text": "The noticeboard is covered in paper." }
{ "cmd": "say", "speaker": "Liisa", "text": "Like this, %player_title%?" }

Dialogue text, the speaker name and choice option text all pass through variable interpolation: %name% is replaced by the variable of that name, or by a setting of that name. An unknown name is left as-is and logged.

Text is always written inline in text today. A text_key is accepted but only shows the key in square brackets — translation lookup is planned. See Localisation.

Backgrounds

{ "cmd": "bg", "image": "bg/noticeboard_closeup.png" }

The path is relative to qml/game/assets/. The image is scaled to fill the screen and cropped to fit. The background changes instantly: a transition key, as seen in the sample script, is accepted but ignored until transitions are planned in.

Sprites

{ "cmd": "sprite", "id": "liisa", "image": "liisa_1.png",     "position": "left" }
{ "cmd": "sprite", "id": "liisa", "image": "liisaBlink.json",  "position": "60%,100" }
{ "cmd": "sprite_remove", "id": "liisa" }

image is relative to qml/game/assets/sprites/ — do not start it with sprites/. It can be:

  • a plain .png, .jpg or .jpeg image, or
  • a .json sprite object: several stacked images with animations, such as a character who blinks. Build one with the sprite object editor. Paths inside the file are also relative to assets/sprites/, wherever the .json sits.

A path containing .., a backslash or a leading / is rejected with a warning, and so is an unknown file type; the sprite is then not shown.

A sprite is 90% of the screen height, and as wide as its first image. position:

  • left and right: against that side of the screen, at the bottom;
  • anything else, or nothing: centred at the bottom;
  • a percentage pair like "60%,100" to place it by hand. The first number is where the sprite's horizontal centre goes, as a percentage of the screen width. The second is where its bottom edge goes, as a percentage of the screen height: 100 stands the sprite on the bottom of the screen, 0 puts it entirely above the screen.

Jumping and labels

{ "cmd": "label", "label": "dont_panic" }
{ "cmd": "jump",  "label": "dont_panic" }
{ "cmd": "jump",  "scene": "scene_0002" }
{ "cmd": "jump_if", "condition": { "var": "panic", "op": ">=", "value": 3 }, "label": "meltdown" }
  • A label jump stays inside the current scene. A scene jump loads that scene and starts at its first command; there is no way to jump to a label in another scene.
  • If a jump has both label and scene, label wins and scene is silently ignored.
  • A jump to a label that does not exist is logged and the script carries on with the next command.
  • Duplicate labels in one scene are not an error: the last one wins, and the earlier one becomes unreachable.
  • jump_if with a false condition falls through to the next command. Conditions are covered in Variables and conditions.
Loops need a tap in them — the engine runs non-waiting commands by calling itself, so a loop made only of jump / jump_if / set commands, with no say or choice inside it, does not loop forever: it crashes the game with a stack overflow. Make sure every loop contains something the player has to tap through.

Choices

{
    "cmd": "choice",
    "options": [
        {
            "text": "Don't panic",
            "condition": { "var": "panic", "op": "<", "value": 3 },
            "label": "dont_panic"
        },
        {
            "text": "Panic",
            "condition": null,
            "effects": [ { "var": "panic", "op": "add", "value": 1 } ],
            "label": "label_panic"
        },
        {
            "text": "Panic in another scene",
            "scene": "scene_0005"
        },
        {
            "text": "Panic hard",
            "effects": [ { "var": "panic", "op": "add", "value": 2 } ]
        }
    ]
}
KeyMeaning
textThe option label. Interpolated like dialogue. (text_key shows a bracketed placeholder for now.)
conditionOption is hidden unless this is true. null or absent means always visible.
effectsList of set-style changes (var, op, value or from) applied when the option is picked.
labelLabel in this scene to continue at.
sceneScene to continue in, from its first command. Same rules as jump: if both are present, label wins.

An option with neither label nor scene simply carries on with the command after the choice. That is deliberate, so you do not have to write a label and a jump for "and then continue". The engine still logs a note, in case it was a typo — if an option does not branch, check the console for that note and the option's key names. The key is label or scene, not next.

If every option is hidden by its condition, the engine warns and skips the whole choice rather than trapping the player — so make sure at least one option has no condition, or the player may never see the menu. How the menu looks is set in the choice style.

Styles mid-scene

{ "cmd": "style", "category": "textbox", "style": "colorful_textbox" }

category is textbox, choice or hud. style is a file name, without .json, from assets/ui/<category>/. The style is built from scratch each time — engine default, then the style's parents, then the style itself — it does not add on top of whatever was active before. If it cannot be loaded, the engine logs a warning and that category goes back to the engine default. An unknown category is logged and ignored. The active style is saved with the game. Build style files with the textbox and choice style generators. A hud style can be switched, but there is no on-screen HUD to apply it to yet.

Audio

Audio files live under qml/game/assets/audio/ and are named relative to it, for example music/Origami.mp3 or sfx/boink.mp3. Every command here scales its volume by the volume slider of its channel on the Settings screen: music for audio_bg, game_fx for audio_fx and looping_fx for audio_loop. These channels always exist; the manifest can relabel them, change their default volume or hide their slider, but does not need to mention them. A volume in a command is a multiplier from 0 to 1 on top of that slider (default 1).

audio_bg — background music

{ "cmd": "audio_bg", "action": "setMusic", "tracks": ["music/Origami.mp3"], "fadeTime": 800 }
{ "cmd": "audio_bg", "action": "setVolume", "volume": 0.4, "fadeTime": 1000 }
{ "cmd": "audio_bg", "action": "pause" }
{ "cmd": "audio_bg", "action": "resume" }
{ "cmd": "audio_bg", "action": "stop", "fadeTime": 2000 }
actionKeysEffect
setMusictracks (required, a list), loop, transition, fadeTime, volume Starts the listed tracks, crossfading away from whatever was playing. Several tracks play in order; with loop (default true) the list starts over after the last one, and a single looping track repeats. "transition": "cut" switches instantly; anything else fades over fadeTime milliseconds (default 800).
setVolumevolume, fadeTimeFades the current music to a new multiplier.
stopfadeTimeFades out and clears the track list. No fadeTime stops at once.
pause, resume—Pauses and resumes the current track.

The music state is saved with the game.

audio_fx — one-shot effects

{ "cmd": "audio_fx", "file": "sfx/boink.mp3" }
{ "cmd": "audio_fx", "file": "sfx/tram_distant.mp3", "volume": 0.5 }

Plays the file once, on the game_fx channel, and carries on straight away. Up to four effects can play at the same time; a fifth is skipped with a warning. That limit is also the hint that long or repeating sounds do not belong here — use audio_loop.

audio_loop — looping effects

{ "cmd": "audio_loop", "action": "start",   "id": "rain", "file": "sfx/rain.mp3", "volume": 0.6, "fadeTime": 1500 }
{ "cmd": "audio_loop", "action": "stop",    "id": "rain", "fadeTime": 1500 }
{ "cmd": "audio_loop", "action": "stopAll", "fadeTime": 500 }

For ambience. id is a name you choose, used to stop that loop later. Up to four loops can run at once. Starting an id that is already playing the same file only adjusts its volume. Stopping an unknown id is logged and ignored. All loops and the music are stopped when a new game starts or a save is loaded.

Things that surprise people

  • Choice options branch with label or scene, never next, and alt_scene does nothing.
  • set copies a value from a variable or setting with a from block. from_setting is not supported.
  • Each kind of path has its own base folder: sprites are relative to assets/sprites/, backgrounds to assets/, audio to assets/audio/.
  • Variables and settings share one lookup namespace for %name% text and flag conditions; see Variables and conditions.
